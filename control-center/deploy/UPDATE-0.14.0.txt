2. Branding now returns ONLY site-owned download links, never build-provider URLs,

   size/hash-bounded APK stream, never shell commands or reseller-selected paths.
   The bridge service needs read-only code/config, original storage keys and images,
   required DB permissions and write access ONLY to storage/brand-apks (shared with
   PHP). Use tightly scoped ACLs/group access; do not chmod the whole site world-writable.

   directory permissions (for example02750), or equivalent default ACLs. Verified APKs
   are0640 so both services can read them; transfer staging starts0600. Do not grant
   this group access to other tenants' data or make config/encryption keys public.
4. Add to your EXISTING private config.php (do not replace it):
     'brand_downloads' => ['enabled' => true, 'x_accel' => false],
   This enables bounded PHP streaming with HEAD/single Range/resume support. There
   are NO redirects or build-provider fetches on public download requests.
   The central builder uploads and SHA256-verifies the APK privately BEFORE the
   website registry can advertise it. Downloads do not depend on GitHub availability.

         alias /REAL/APP/FOLDER/storage/brand-apks/;

         add_header X-Content-Type-Options nosniff always;

   Nginx must be able to read only the APK files/directory via scoped ACLs; existing
