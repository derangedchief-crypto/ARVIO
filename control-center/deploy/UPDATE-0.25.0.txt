NEW RULES (compatible client required):
- Only a verified activation code can establish/change the app's pinned primary.
  Playlist reordering, labels, source IDs, cloud imports and restores cannot do so.
- Invalid/expired primary blocks ordinary app use and controlled playback, even
  when an extra line and the reseller's licence are otherwise valid.
- A valid primary without an active Extra Playlists entitlement is primary-only.
  ALL existing extras count, regardless of when the customer or source was added.
- Existing data is retained, not deleted. Legacy installations without a trusted
  binding require one activation-code confirmation, preserving existing extras/IDs.
- Outage grace is at most15 minutes since a successful validation, bounded by any
  earlier known primary/licence expiry. Confirmed negatives end permission now.
  Retry does not extend grace. Positive grants are memory-only; process/device
  restart requires online verification, never a fresh offline grace window.
- Uncontrolled casting via the stock receiver is unavailable in the guarded client:
  it cannot enforce expiry after the controlling app is gone. Existing APKs and
  third-party sessions already handed off cannot be retroactively controlled.

Server add-on checks use the already enrolled account's signed, read-only panel
line status; they never choose a secondary playlist. Worker outages fail new
additions closed. The client may retain previously verified playback only for
the bounded outage grace. No direct panel DB credentials are added to the website.

Before enabling enforcement: test expired trial + valid extra, old extra sources,
key revocation during playback, primary renewal, server outage past the deadline,
reordering/profile/restore/resume attempts and intact saved data. Older/unupdated
or modified APKs are not claimed to enforce these rules.
