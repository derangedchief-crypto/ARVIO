MERCHANT SETUP (each reseller's OWN accounts):
1. Customer renewals -> Connect Stripe or Connect Square reserves the final webhook
   URL before asking for endpoint-specific signing credentials. The URL is stable
   across cancelled/retried setup until that setup is completed.
2. Create the provider webhook using that EXACT URL in the matching sandbox/live
   account. Stripe events: checkout.session.completed,
   checkout.session.async_payment_succeeded, checkout.session.expired.
   Square events: payment.created and payment.updated.
3. Enter the API credentials and endpoint signing secret/key in the website ONLY.
   Square needs its actual active, card-enabled Location ID. Stripe restricted
   keys need account read, Checkout Sessions read/write and PaymentIntent/Charge
   read. Square tokens need merchant/location read, orders read/write and payments
   read/write. The website reads/verifies the merchant before saving credentials.
4. Save, then send a provider test notification and verify delivery. Keys are
   encrypted/write-only. Rotation retains old orders and their signing evidence.
5. Set preferred and alternative gateways for USA/Canada, and appropriate customer
   money prices for the offered current packages. Square requires its location's
   currency. Stripe initially supports USD/CAD. No currency conversion is guessed.
